### 배경

챗봇 시스템 운영 중, 이용자 급증 시 메시지 전송 API의 응답 속도가 저하되고 시스템 전체가 버벅이는 현상에 대해 제보를 받았다. API에 대해 분석을 해보니 메시지 전송 시 금칙어를 필터링하는 로직이 포함되어 있었다. 필터링 결과에 따라 경고 문구 전송 및 세션 강제 종료 등의 처리로 이어질 수 있다.

### 문제 파악 및 분석
> 정확한 문제 파악을 위해 부하테스트, APM 도구를 활용하여 분석을 진행하였다.

- **병목 지점 분석:** 전체 트레이스 데이터를 분석한 결과, 요청 처리 시간의 80% 이상이 Elasticsearch를 호출하는 특정 Span에 집중되어 있음을 확인하였다.
	
- **스레드 고갈:** 동시 요청이 증가할 경우 Elasticsearch 로의 I/O 시간이 급증하였으며, 해당 문제는 서버의 **스레드 고갈**로도 이어져 챗봇 시스템의 전반에 영향을 끼칠 수도 있다는 것을 알 수 있었다.
    
### 원인 분석 및 대안 탐색 
- **기존 방안의 한계:**
	- 단순 문자열 매칭을 위한 Elasticsearch 와의 외부 통신으로 인해, 대량 트래픽 발생 시 **불필요한 네트워크 I/O 비용**과 응답 지연이 발생
		
	- 금칙어 사전을 갱신할 때 기존 Elasticsearch (Nori) 형태소분석기의 커스텀 사전 업데이트가 되지않아 감지 대상에서 누락되는 정합성 문제 발생
        
- **대안 탐색 및 결정:**
    - "단순 금칙어 필터링에 무거운 형태소 분석기가 필수적인가?"라는 의문을 바탕으로 접근하여, **Elasticsearch 의존성을 제거하여 시스템 복잡도를 낮추는 것을 목표로 설계를 재검토**
        
    - 금칙어 처리하는 여러 실무 사례를 분석하였고, 그 결과 별도의 검색 엔진 없이 인메모리 방식만으로 더 강력한 성능을 낼 수 있는 **아호코라식(Aho-Corasick) 알고리즘** 도입을 최종 결정 (참고 사례: [배달의민족 기술블로그](https://techblog.woowahan.com/15764/)))
            
### 해결
- **In-Memory 기반 필터링 구축:**
    - 애플리케이션 실행시점에 금칙어를 Trie 자료구조로 로드하여, 외부 통신 없이 고속으로 필터링 수행 (라이브러리: `org.ahocorasick`)
            
- **분산 환경 데이터 동기화:**
    - 관리자 페이지에서 금칙어 변경 시, RabbitMQ Fanout Exchange를 활용해 모든 서버 인스턴스에 변경 이벤트를 브로드캐스팅하여 실시간으로 인메모리 Trie 재구축 및 동기화 구현.
            
### 성과
- **처리속도 개선**: 1,000 문장 기준 처리 시간 약 90,000ms → 50ms로 단축하고, 시스템 성능과 안정성을 확보할 수 있었다.

- **운영 효율성 증대:** Elasticsearch 커스텀 형태소분석기 기반의 금칙어 관리 기능 아키텍처를 단순화하고, 네트워크 비용 및 장애 포인트를 낮췄다.
